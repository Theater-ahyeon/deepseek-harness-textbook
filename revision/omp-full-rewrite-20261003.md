### 第 2 章

**改写前**

Promise 表示异步操作的结果，状态包括等待中、成功和失败。`async` 函数返回 Promise，`await` 暂停当前函数的后续执行，等待该结果；JavaScript 运行时在此期间可以处理其他就绪工作。进程由操作系统管理，线程是进程内的执行路径。并发允许多项工作交错推进，并行使用多个执行资源在同一时刻处理工作。操作能否重叠，取决于启动和等待顺序。回调是供其他代码在约定时机调用的函数，例如事件监听器。阅读 `() => ...` 时，需要定位它的注册位置、调用者和触发条件。

**Gemini 初稿**

异步操作开始后，程序通过 Promise 获取结果，它包含等待中、成功或失败三种状态。声明为 `async` 的函数会给出 Promise，内部通过 `await` 暂停自身后续流程以等待该结果；此时 JavaScript 运行环境有能力去推进其他就绪任务。操作系统负责管理进程，而线程充当进程里的执行线索。并发让多项工作交替向前推进，并行则是在同一时刻投入多个资源处理任务。各项操作能否重叠发生，由它们的启动时间与等待安排决定。回调是留给其他逻辑在约定条件满足时触发的函数，例如各类事件监听。阅读 `() => ...` 时，要认清它在哪注册、被谁调用以及触发时机。

**复审后采纳版**

异步操作开始后，程序通过 Promise 获取结果。结果尚未确定时，Promise 处于等待状态；操作完成后，它转为成功或失败。`async` 函数返回 Promise，`await` 暂停当前异步函数的后续执行，等待结果。在这段时间内，JavaScript 运行时仍可处理其他就绪工作。

进程由操作系统管理，线程是进程内的执行路径。并发允许多项工作交错推进，并行则使用多个执行资源同时处理工作。两项操作能否重叠，要看它们何时启动、何时等待，不能只凭 `async` 关键字判断。

回调是交给其他代码、由它在约定时机调用的函数，例如事件监听器。阅读 `() => ...` 时，需要找到它的注册位置、实际调用者和触发条件，才能判断这段函数体何时执行。

## 技术复审中的重点修正

- requestId 在目标 Agent 的 Inbox 和 Session 用户消息中去重；seq 表示当前 Session 的事件登记顺序。
- accepted 确认输入接纳；Session.append 建立内存事实；后台写入和 flush 等待分别说明。
- cancel 默认清空 Inbox；设置 keepInbox 才保留待处理输入。
- read 保留原始路径字符串，验证有限正整数；文件大小达到阈值或未知时采用流式路径，输出截断后继续扫描以计算总行数。
- Skill 同名选择先按 scope 层覆盖，同一层再按 Provider 排序；获取完整定义后继续复查入口许可。
- compaction 按序追加记录，失败保留此前已追加内容；结束标记追加失败后不会反复追加。
- DeepSeek Adapter 忽略 iterator.return 的清理异常，避免覆盖已有结果。
- 审批取消表示结束审批等待，工具执行与外部动作另外判断；MCP 交换失败清空的是本地注册。
- 任务评分、完整实验记录和费用公式作为教学评价方法说明，TokenMeter 与遥测提供运行数据。
- Cordis 的同层 disposer 并发等待，严格依赖在同一 disposer 内顺序 await；作用域标签与进程隔离分别解释。
