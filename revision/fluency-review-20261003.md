## 技术调整

| 核验点 | 本轮讲解 | 章节 |
| --- | --- | --- |
| 输入检查发生在哪里 | 工具执行先经过 ToolRuntime 准入，再由 defineTool 的包装函数检查 schema，read 执行体解析参数和默认值。 | 4、11、18 |
| 输出与展示错误怎样处理 | schema、render 和顶层 presentationMeta 错误进入工具错误链；Web Client 从原始事件派生卡片。Host 的 presentCall/presentResult 留给本地消费方。 | 18 |
| JSONL 的持久写入与回退 | 存储监听器先缓冲；writer 写入包含文件同步。写入或同步失败后截回原长度并同步，回退失败报告组合错误。 | 5 |
| 压缩选区保留调用配对 | 选区从首个非 system 节点开始，保留近期尾部，并检查选区两端配对平衡；尚未关闭的步骤留在选区之外。 | 8 |
| 模型输出上限的停止顺序 | max-tokens 是输出上限。循环先保存助手消息，再在提取和执行 Tool Call 之前返回停止原因。 | 3、9 |
| config 按字段整体覆盖 | 补丁按 id 定位，并直接给条目字段赋值；config 是整个字段。insert 立即加入索引，后续补丁可修改新条目。 | 10 |
| 事件缺口由 Host 检查 | SessionHistoryController 先监听、缓冲、获取快照，再检查事件序号。缺口抛出 gateway/internal，finally 释放监听器。 | 14 |
| 客户端历史重建与控制流分开 | resync 关闭旧历史来源并重新 open；投影状态由独立重连的控制流维护。此方法在地址替换时触发。 | 14 |
| 回放缺失终结与 override | 缺少 finish 的录制无法直接派生响应；整份数组可替换脚本，patches 在可派生脚本上修改指定位置。 | 16 |
| Cordis 同层释放的执行方式 | 同层 disposer 映射为异步任务，再由 Promise.all 等待。每项错误独立捕获并记录。 | 19 |
| Web Client 直接派生工具卡片 | Conversation 配对原始事件，ToolCallTree 按名称分派 keyed slot；readCardModel 校验调用、metadata 和输出格式，不匹配时返回 null。 | 18 |
