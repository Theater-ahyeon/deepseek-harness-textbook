# 第 7 章｜Skill 发现与按需加载

本章学习任务：追踪 Skill 的目录发现、入口检查与正文读取，区分工作方法与工具执行权限。

## 07.1 基本概念

Skill 是封装任务方法的说明及相关资源，例如技术报告的整理流程。目录摘要公开名称和用途，正文解释操作步骤与要求。模型通过摘要发现候选，在需要使用时读取对应正文。

Skill 服务负责发现、列出和读取定义，`skill` 工具让模型按名称获取正文。调用权限分别声明是否允许用户调用、是否允许模型调用；读取入口按相应标志检查。目录可见性用于发现候选，调用标志决定能否从这一入口加载。

Skill 加载获取正文并将其加入模型上下文。正文指导模型组合已有工具，文件访问、网络调用和发布操作仍由工具注册、准入与执行环境控制。用户显式指定 Skill 和模型调用 skill 工具分别采用对应的读取路径。

需要区分三个观察点：目录是否包含名称，读取是否获取定义，正文是否进入本次请求。排查未按 Skill 步骤执行的故障时，先找这三个证据，再评价正文的方法是否清楚。

## 07.2 沿一个任务看完整流程

假设目录包含 report-skill，摘要标明其用于整理技术报告。模型先根据摘要匹配任务需求，再调用 Skill 读取工具。工具根据当前工作目录、Agent 范围和取消信号获取目录，找到名称以后检查它是否允许模型调用；通过后再获取完整定义。

若目录里的定义已经移除，查询不到名称就报错；名称仍可见但禁止模型调用时，工具返回入口限制错误。获取正文以后，框架把它整理成模型材料，后续模型请求便能使用其中的方法。

用户显式调用的入口会检查用户可调用条件，符合时才建立 Skill 调用来源的指令消息。未知名称和不符合条件的文字不会都被解释为命令。正文中的方法通过后续模型推理与工具调用落实。

## 07.3 关键机制与设计取舍

### 先知道名称，再获取正文

![F07A：目录发现、指定读取与 Skill 正文](../figures/F07A.png)

图 07A 沿模型调用路径展开：发现候选、发布摘要、选中名称、检查模型调用许可、获取正文。正文作为工具结果记录，随后进入下一次模型请求。

### 注册表与 Provider 分别负责什么

`SkillRegistry` 管理可见 Provider 和候选。文件系统 Provider 负责从相应目录发现 Skill 并读文件内容。`list` 返回摘要列表；`get` 按名称选择候选；同名项依次按 Provider 优先级、Provider 顺序和本地顺序取舍，把候选定位信息返回对应 Provider 读取，再校验完整定义。这使消费方不必固定绑定某个文件目录实现。

工具插件在前置步骤把当前 Agent 可调用的 Skill 目录写成持久提示消息。目录包含名称与说明，正文按需读取。目录发生变化时，插件发布替换消息；发现过程不完整时，保留已有目录。模型调用 `skill` 后，执行体检查名称、可见摘要和模型调用标志，再获取完整定义并返回正文。

用户直接调用走另一条路径。前置步骤检查直接用户消息第一行的 `/<name>`，名称存在且允许用户调用时，加载正文并注入本步消息。模型调用 `skill` 工具则把正文记录为工具结果，供后续步骤使用。消息来源与调用标志决定这两条路径各自何时生效。

### 按需加载与工具权限

按需加载在任务需要时获取 Skill 内容。正文提供工作方法，工具注册决定可调用能力，准入链决定本次调用是否允许，执行环境限制实际资源访问。这些控制机制在加载后继续生效。

目录摘要帮助选择 Skill，正文提供步骤、参数和限制。例如“用于文档整理”只说明用途，具体怎样整理要在加载正文后确定。Provider 读取失败、名称消失或入口禁止调用时，工具返回对应错误。

### 分析示例：按需材料量

教学目录有三个 Skill，正文分别是 2000、3000、5000 字节，目录摘要合计 600 字节。本次只获取第一个 Skill，目录加正文为 2600 字节；若都加载则为 10600 字节，差额 8000 字节。计算假设两种方案都携带同一目录，忽略其他请求材料。

复算记录：[C7 · Skill 材料用量](../examples/calculation-results.json)。

按需方案省去未选中 Skill 的正文，同时增加查找和读取操作。评价时需要同时记录材料量、加载次数和任务结果。摘要准确性、选择结果与正文版本影响加载所得的方法是否适合当前任务。

### 回到项目说明整理

![F07B：全部正文与只取所需正文的材料对照](../figures/F07B.png)

图 07B 左侧携带三个 Skill 的全部正文和同一目录，共 10600 字节；右侧携带目录与第一个正文，共 2600 字节，差额为另外两份正文的 8000 字节。

Skill 正文指导报告结构，read 结果提供项目事实。模型把两者结合，生成注明来源和限制的总结。

### 常见误解

“目录列出一百个 Skill，所以上下文已包含一百份全文”：目录与正文有不同契约，应查看实际获取材料。

“任何页面里出现 /Skill 名 都会触发”：直接调用手势有消息来源与可调用策略限制。

“Skill 加载后可以绕过工具准入”：Skill 改变材料和工作方法，准入仍在第十一章的工具链里。

## 07.4 源码研读

<a id="e07a"></a>

### E07A · 读取正文前的可见性和入口检查

阅读任务：这是 Skill 读取工具执行体中的节选。args.name 是请求的名称，exec 提供 Agent 与取消信号；重点区分目录查询、模型调用条件与获取正文。后续结果构造不在本段。

#### 实现详解

模型调用 skill 工具时，需要把名称解析成当前 Agent 可读取、可调用的完整定义。工具先检查名称格式，随后建立 lookup 查询条件：工作目录来自 Agent 的 Session，scope 使用当前 Agent，signal 传递本次调用的取消信号。目录发现和正文读取都使用这组条件，因而沿当前 Agent 的插件装配与工作区解析候选。

工具先调用 skills.list 获取摘要目录，再查找与 args.name 相同的条目。目录里没有这个名称，就报告未知或已经不可用；找到摘要后，再检查它是否允许模型调用。某个 Skill 可以被发现，却只允许用户显式调用，这种候选在模型入口会被拒绝。摘要在这里同时提供发现信息和入口策略，正文尚未进入结果。

摘要检查通过后，skills.get 才获取完整定义。两次异步查询之间，Provider 的可用状态或文件可能变化，所以 get 返回空时仍要报告不可用。紧接节选的代码还会检查完整定义的模型调用标志，通过后才把名称、Provider、可选资源基址与 content 组织成结果。资源基址为正文引用的相关资源提供定位信息，content 保存实际方法说明。

例如模型选中 report-skill：当前目录里没有它时停止于摘要查找；目录存在但只允许用户调用时停止于入口检查；目录允许且完整定义有效时，工具返回正文。正文再由输出渲染与工具结果记录进入后续模型请求，指导报告结构。接下来的文件读取仍使用已有工具链和准入规则。由此，候选发现、入口许可、完整读取和上下文使用构成四个相连的阶段。

## 07.5 理解检查与讲解问答

### 问题 1 · 看到 Skill 摘要以后，正文是否已经可用？

讲解：还没有。摘要帮助选择，读取工具获取完整定义后才能形成正文材料。

### 问题 2 · Skill 可见但不允许模型调用，会怎样？

讲解：读取入口检查调用条件，不能因名称出现在目录中就放行。

### 问题 3 · Skill 能否自行提高工具权限？

讲解：不能。Skill 提供方法与说明，真实工具仍经过本身的准入和执行限制。
