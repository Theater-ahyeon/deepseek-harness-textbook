# 第 4 章｜文件读取：参数解析与窗口构造

本章学习任务：理解 read 的参数校验、文件访问和窗口构造，分析缺失文件与输出截断的处理。

## 04.1 基本概念

文件路径标识读取目标，当前工作目录是相对路径的解析基准。Session 与所选文件 Provider 共同确定 `README.md` 对应的实际位置。后端实现统一文件接口：接口规定读取操作及返回形式，具体后端负责本机、远端等环境中的路径解析和文件访问。

工具参数契约规定可接受的字段、类型和值。schema 描述字段结构，例如字符串路径和数字行号；解析逻辑进一步检查取值、补齐缺省参数，并转换成执行体使用的内部输入。读取窗口保存本次选定的文本行，同时返回总行数与截断信息，供模型判断是否需要续读。

流式文件读取按批次向窗口构造器提供文本，避免在内存中保存整个大文件。模型流式响应则按批次返回生成内容，两者分别作用于文件输入和模型输出。读取结果受行数、单行长度和输出字节上限约束，并明确标示实际保留范围。第 18 章进一步说明结构化结果如何生成模型文本与界面元数据。

字节是存储和传输数据的计量单位。UTF-8 把文字编码成字节序列，一个汉字通常占多个字节。模型的 tokenizer 又把文字编码成 token。文件字节数、文本行数和模型 token 数采用不同计量规则，工具输出上限与模型容量分别控制。

读取前要经过通用工具准入；获准后依次解释参数、选择读取方式并构造窗口。拒绝调用与读取时发现文件不存在，是两个独立阶段的结果。

## 04.2 沿一个任务看完整流程

假设 README 有五行，工具参数是路径 README.md、offset 为 2、limit 为 2。调用先经过 ToolRuntime 准入；获准后，defineTool 包装函数检查参数的 schema，read 执行体再检查路径不为空、行号与行数为正整数。合法输入变成内部的 filePath、offset 和 limit。文件服务解析目标、获取文件信息，然后依大小信息选择一次读取或流式读取；窗口构造器保留第二、三行，并受其他输出上限限制。

如果不提供 offset，使用第 1 行；不提供 limit，采用本次配置的默认上限。提供 0、负数或超过允许上限的 limit，会走参数错误分支。文件大小未知时采用流式路径，是为了避免无法判断大小的后端先缓存任意大文件。

结果返回后，ToolRuntime 校验并渲染输出，驱动再记录工具结果。下一次请求得到的是这次读取的窗口，窗口中的行号和总行数帮助模型决定是否续读。

## 04.3 关键机制与设计取舍

### 一次读取的材料变化

![F04A：读取参数怎样变成文件片段](../figures/F04A.png)

图 04A 从路径和行范围走到文件服务，再构造行窗口、渲染模型文本并记录结果。通用准入先决定是否分派，工具执行阶段再完成参数校验和实际读取。

`read` 接收 `file_path`、可选 `offset` 和 `limit`，起始行从 1 开始。参数 schema 描述字段名称、类型和必填要求；`parseReadArgs` 检查路径非空、行号和行数为正整数，并应用配置上限与默认值。

### 启动注册与调用执行

启动时，文件工具插件获取所需服务，调用 `applyReadTool` 注册工具定义，并贡献对应使用指导。定义里同时有说明、参数、执行体和输出呈现契约。此时没有读用户指定的文件。

实际调用先经过通用工具准入，由安全策略判断是否放行，详细规则见第 11 章。获准后，包装函数检查 schema，`read` 执行体解析参数，再通过 `resolveRegularReadTarget` 获取目标和文件信息。文件较小时整读，大小未知或达到阈值时流读。`buildWindow` 按行范围、单行长度和字节上限保留文本，同时继续扫描剩余输入，统计准确的总行数。结果因此可以同时告诉模型“本次返回哪几行”和“整份文件有多少行”。

`ctx.fs` 由当前 profile 选中的文件 Provider 实现。本机 Provider 访问本机路径，SSH Provider 访问远端路径；read 通过同一接口调用它们。读取结果随后分成模型文本和界面展示元数据，第 18 章会把这两条输出路径连起来。

### 行、字符和字节

行数、单行长度和输出字节数共同控制返回体积。长行先截到规定长度，再按 UTF-8 字节数检查能否加入窗口。模型随后对这份文字作 token 编码，所以读取 100 行时，token 数还要根据具体内容计量。

参数错误在读取前返回。路径不存在或目标不是普通文件时，目标解析报错，再由通用结果链形成工具错误。达到字节上限时，窗口停止保存后续行，继续统计总行数，并在成功结果中标明截断。

### 分析示例：读到哪些行

教学文件有 120 行，请求从第 41 行读取 30 行，且本例假设字节与单行长度限制没有提前截断。最后一行是 41＋30−1＝70，所以返回 41—70 行，后面仍有 50 行。

复算记录：[C4 · 行窗口计算](../examples/calculation-results.json)。

若重要约束在第 100 行，就要继续读取后面的窗口。若字节上限让结果提前停在第 60 行，实际覆盖范围是 41—60 行；续读应从第 61 行开始。每次都以返回结果中的范围为准。

有限窗口降低材料体积并让来源更容易定位，代价是需要正确续读和识别遗漏。整体读取先获取完整文本，流式读取分批交给窗口构造器；两条路径都应用同一组输出上限。

### 重走 README 任务

![F04B：完整文件与有限返回窗口](../figures/F04B.png)

图 04B 把 120 行文件分成三段：第 1—40 行在窗口前，本次返回第 41—70 行，第 71—120 行留待续读。正文中的行范围说明本次结果覆盖哪里。

### 常见误解

“read 成功等于全文进入上下文”：检查行窗口、截断和实际结果。成功与完整性是不同属性。

“模型能直接执行参数里的任意路径”：先有工具准入，再有文件服务的解析与执行边界，不能略过这些层。

“行数限制就是 token 预算”：单位不同，材料统计与模型 token 计量需要分别进行。

## 04.4 源码研读

<a id="e04a"></a>

### E04A · 参数默认值与错误分支

阅读任务：这是 parseReadArgs 完整函数。调用者把模型提交的外部参数和配置上限交进来；本次观察缺省值与不合法值怎样区别处理。

#### 实现详解

parseReadArgs 连接 read 的外部参数接口与内部执行逻辑。外部调用使用 file_path、offset 和 limit；包装函数已经检查这些字段的结构与类型，本函数进一步检查具体值，并为缺省项建立明确规则。maxLimit 来自插件配置，既是未指定 limit 时使用的默认行数，也是允许请求的最大行数。

路径首先经过非空检查。函数对 file_path 的临时值去除首尾空白，再检查长度；空字符串和纯空白路径被拒绝。通过检查后，返回对象仍保留原 file_path 字符串，只把属性名改成内部使用的 filePath。因此，这里的 trim 服务于非空判断，实际路径解析仍交给后续文件服务。

行参数分别处理“没有提供”和“明确提供”。offset 缺省时取 1，表示从文件第一行开始；limit 缺省时取 maxLimit。提供的值则必须是有限的正整数，所以 0、负数、小数以及非有限数字都会报错。limit 通过正整数检查后还要与 maxLimit 比较，超过上限直接拒绝。合法的 offset 可以大于文件总行数，是否越界由读取与窗口构造阶段结合实际文件判断。

例如配置 maxLimit 为 100，调用只给出 README.md 和 limit=2，得到内部输入 filePath=README.md、offset=1、limit=2。给出 limit=0 会在正整数检查中失败，给出 limit=101 会在上限检查中失败。只有完整参数通过后，执行体才解析目标、获取文件信息并读取。默认值、参数错误和文件错误各在对应阶段形成结果，便于定位一次读取在哪一步停止。

代码类型：**真实源码摘录**。证据编号 [E04A](../evidence-index.md#e04a)；下表的数字是原文件行号。

```ts
export function parseReadArgs(args: { file_path: string; offset?: number; limit?: number }, maxLimit: number): ReadInput {
  if (args.file_path.trim().length === 0) throw new Error('file_path must be a non-empty string')
  const offset = args.offset === undefined ? 1 : parsePositiveInteger(args.offset, 'offset')
  const limit = args.limit === undefined ? maxLimit : parsePositiveInteger(args.limit, 'limit')
  if (limit > maxLimit) throw new Error(`limit must be less than or equal to ${maxLimit}`)
  return { filePath: args.file_path, offset, limit }
}
```

| 56 | trim 去首尾空白，if 与 throw 建立错误分支 | 空白路径不能进入文件解析和读取。 |
| 57 | 三元表达式根据 undefined 选值 | 未提供 offset 用 1，提供了则检查正整数。 |

### E04B · 大小信息决定文本获取方式

阅读任务：位置在 read 的执行体内，参数已经解析。target 保存后端解析的目标，info 保存文件信息，caps 是本次读取限制，exec.signal 是取消信号，ctx 是携带各项服务的 Context 对象。后续 outcome 和结果返回在正文中说明。

#### 实现详解

read 的执行体取得合法参数后，需要解决两个连续问题：怎样获取文件文本，以及怎样从文本中构造本次返回窗口。它先调用 resolveRegularReadTarget，由当前文件 Provider 解析路径并确认目标适合普通文件读取。返回的 target 表示后端可访问的目标，info 提供文件信息，包括可选的大小；target.displayPath 用于在结果中显示路径。

获取方式由文件大小和配置阈值决定。大小已知且小于 streamMinSize 时，一次 readText 获取完整文字，再包装成单个文本批次；大小达到阈值或后端没有给出大小时，streamText 提供逐批文字。未知大小选择流式路径，避免先缓存一个无法判断体积的完整文件。两条文件接口都接收 exec.signal，将本次调用的取消信号传递给后端。

接下来，两种输入统一交给 buildWindow。它按 offset 跳过窗口之前的行，最多保存 limit 行，同时应用 maxLineLength 和 maxBytes，分别控制单行长度与输出字节数。流式路径按批次提供文字，一次读取路径提供一个完整批次；窗口构造器处理跨批次的行边界，并继续扫描剩余输入以统计总行数。获取方式决定文本怎样到达，窗口规则决定最终保留哪些内容。

假设文件有 120 行，请求从第 41 行取 30 行，其他上限没有提前截断，窗口保存第 41—70 行，并报告总行数 120。若字节上限使保存停在第 60 行，结果保留第 41—60 行，仍统计完整文件的行数。执行体随后用窗口建立规范值，并记录本次文件观察；输出契约再生成模型文本和展示元数据。后续模型据实际返回范围决定是否从第 61 行继续读取。

代码类型：**真实源码摘录**。证据编号 [E04B](../evidence-index.md#e04b)；下表的数字是原文件行号。

```ts
      const { target, info } = await resolveRegularReadTarget(ctx, exec, input.filePath)

      // Stream when the file is large OR size is unknown, so a size-less backend
      // never buffers an arbitrarily large file.
      const chunks = info.size === undefined || info.size >= caps.streamMinSize
        ? await ctx.fs.streamText(target, exec.signal)
        : [await ctx.fs.readText(target, exec.signal)]
      const window = await buildWindow(
        chunks,
        { offset: input.offset, limit: input.limit, maxLineLength: caps.maxLineLength, maxBytes: caps.maxBytes },
        target.displayPath,
      )
```

## 04.5 理解检查与讲解问答

### 问题 1 · offset=2、limit=2 是否代表文件只有两行？

讲解：offset=2 指定从第 2 行开始，limit=2 指定最多返回 2 行。整个文件的行数由结果中的总行数信息给出。

### 问题 2 · 未提供 limit 与提供 limit=0 一样吗？

讲解：不同。缺省采用配置默认值；0 不满足正整数条件，走参数错误。

### 问题 3 · 未知大小的文件为什么走流式路径？

讲解：避免先缓存一个无法判断大小的完整文件，同时让窗口处理接收有界输出所需的批次。
