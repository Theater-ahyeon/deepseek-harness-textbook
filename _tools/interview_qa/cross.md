> 本节是跨章综合题：面试官把多个子系统的机制放进同一个场景里追问。回答按"先定位层，再给证据，最后说边界"组织，引用可在[可选证据附录](source-excerpts.md)复核。

### S1 · 场景题：模型陷入了循环——反复读取同一个文件、重复提交相似命令。你如何定位、如何设防？

**定位**：先取会话事实分类循环的层次。是同一步内的模型重试（查 attempt 记录与 `agent/request-error` 链），还是跨步骤的行为循环（查连续步骤的 `tool/call` 事实：名称与参数是否相似）。工具链记录每次调用的序号与参数，所以"重复读取"可以从相邻 tool/call 事实直接比对出来，不需要猜。

**设防**（按层给机制）：材料层——读取结果进入历史后，压缩要保留关键约束（`assertStable` 保证摘要提交不覆盖新事实）；结果层——超长结果走 spill，模型看到定位符而不是反复全量读取；行为层——审批与守卫可以对高风险工具要求人工确认（成对的 `approval/asked`/`approval/decided` 事实）；流程层——Round 上限与阻塞语义（第 9 章 Goal）防止无进展续跑。框架提供的是这些可组合的机制与完整事实，"识别这是循环"的判断逻辑属于部署方或更上层的策略。

**原理**：循环的根源通常是"模型没有从上次结果得到新信息"：窗口没变、约束丢了、或错误结果没有进入下一步材料。防范循环的核心策略在于保证每次工具结果真实、完整、可区分地进入下一次组装——信息流正常时，理性模型不会重复执行无效调用；信息流中断时，单纯的重复检测无法恢复任务推进。

**追问**：能不能干脆在工具链里写死"同一工具同一参数只允许调用一次"？
**回答要点**：不能一刀切——重读是合法需求（文件可能被修改，fs/observed 版本事实就是为此设计）；正确位置是策略层（准入/守卫）按工具与场景配置，而不是在通用链里硬编码业务规则。

### S2 · 场景题：长任务跑到一半进程崩溃，用户刷新页面。哪些东西能回来，哪些不能？为什么？

**能回来**：所有已提交的会话事实——消息、工具调用与结果、轮次边界、压缩替换记录——因为 JSONL 提供方把它们写入磁盘（注意 append 返回不等于落盘，flush 才是等待边界，packages/session/session-persistence-jsonl/src/storage.ts 第 535—546 行）；投影状态可从日志重建；客户端刷新后按快照＋游标重新跟随（教材 6.1.7）。跨了 generation 的旧格式走迁移读取（教材 3.5）。

**不能回来**：崩溃时在途的模型流（未结算的片段既不是成功也不是失败，恢复时不能凭空补造完整模型流，教材 3.5）；PTY 原始状态与进程内终端；外部浏览器的登录与页面状态（教材 6.5）；已发出但未确认的外部动作只如实报告，不自动重放（教材 5.5）。

**原理**：分界线是"事实是否已越过持久化边界并被结算"。事件溯源架构里，磁盘上的事实序列是唯一真源，任何恢复都是从某个前缀重建；没有越过边界的东西（内存里的流片段、进程资源）从未成为事实，假装恢复它们等于编造历史。这也是为什么恢复与迁移必须分开：迁移处理"怎么读旧文件"，恢复处理"从哪个事实前缀继续"。

**追问**：刷新后那半段流式文字为什么没有逐字恢复？
**回答要点**：临时流与持久事实保存方式不同；快照可携带当时的流状态，但不承诺每个 chunk 都作为独立历史保存（教材 6.1.7）。

### S3 · 场景题：给你的团队设计"危险命令必须二次确认"——用 DSH 的哪些机制？审计时看什么？

**机制组合**：①准入层：`tools/pre-execute` 前置链对高危工具返回 ask（packages/core/tools/src/index.ts 第 1504—1511 行）；②审批层：审批服务成对记录 `approval/asked` 与 `approval/decided`，必须在开放轮次内闭合（packages/interaction/user-approval/src/index.ts 第 224—233 行）；③效果层：沙箱预设限制进入执行后的文件范围（read-only/workspace-write），后端如实报告 full/partial；④守卫层：guard 在审批后仍可否决，防止把该拒绝的调用升级为授权。

**审计**：`approval/asked`（谁被问、什么工具、什么理由）与 `approval/decided`（结论）成对出现；`tool/call` 事实给出实际执行的名称与参数；两者对得上，才说明"每次危险执行都有一一对应的人工确认"。

**原理**：四层各防一种绕过：只做审批不设沙箱，批准后的动作没有效果边界；只设沙箱不审批，静默的越界尝试没有记录；guard 单调否决堵住"策略拒绝被别处放行"的口子。成对事件则是可审计性的最小单元——只有 asked 没有 decided 说明流程被中断，只有 decided 没有 asked 说明有绕过路径。这套设计的通用原则是：授权（能不能做）、效果（做了影响什么）、审计（做过什么）是三个独立属性，任何把三者压成一层的方案都会留下绕过面。

**追问**：用户批准一次后，同会话第二次相同命令还要再问吗？
**回答要点**：按当前实现，allowed-once 是这次审批的结论，下一次调用重新走当时的准入规则；要实现"会话内记住批准"属于策略层扩展，且要考虑教材 4.7 的一次性授权原则。

### S4 · 场景题：上下文撑爆了（context-overflow），系统里实际会发生什么？你会怎么验证修复有效？

**发生什么**：溢出错误进入请求恢复路径；基本压缩插件在恢复路径尝试处理：先按需剪枝再 `selectCompactableRange`，没有合适区域返回 null 放弃（packages/compaction/compaction-basic/src/index.ts 第 294—301 行）；选到区域则走 摘要 → `assertStable` → `commitCompactionBody` → `compaction/end` 的流程（region.ts 第 232—245 行）。压力路径失败只警告并继续前置链；溢出恢复受目标策略与次数限制，不是无限重试（教材 2.3.3）。

**验证**：两层分开验——工程行为用回放：固定含溢出恢复的旧轨迹，断言恢复后请求材料包含摘要、`compaction/end` 正常闭合、fixture 完整消费（`assertConsumed`）；业务效果用真实任务评价：同任务集对比压缩前后"关键约束是否保留"与通过率（教材 2.3.7 的摘要甲乙对比），并按第 7 章四口径记录摘要生成的一次性成本。

**原理**：溢出恢复是"错误驱动的前置处理"：它发生在请求失败的恢复路径上，与压力路径（请求前预防）触发点不同、可用的信息不同（溢出时已知超限，压力时只有估算）。分两条路径的原因是失误模式不同：预防失败可以照常尝试（最坏是再溢出一次），恢复失败必须受次数限制（否则在同一个溢出上无限循环）。验证方法分层的原理与第 7 章 Q4 相同：回放证明确定性回归，任务评价证明有损摘要没有伤害质量——两类命题的证据不能互相借用。

**追问**：摘要丢了"某功能尚未稳定"，后续回答出了错，算谁的？
**回答要点**：归因看压缩事件与摘要内容（2.3.7）；有损表达是机制属性，缓解办法是压缩策略保留约束类信息＋spill 给全文定位符，而不是宣称摘要有损但无害。

### S5 · 综合论述题：回到面试官那个问题——"自己手写 Agent 和用现成 Harness，本质上有多大区别？"请用这本书的机制给出完整版回答。

**回答**：区别体现在五组能力上，每组手写都可以做，但 Harness 给出的是成体系的契约：

①输入与推进：手写常是"一个 while 循环收消息"；DSH 有接纳契约（重复 requestId 识别、accepted 语义）、收件箱三入口（followup/steer/inject 差异化进入时点与唤醒）、turn/step/attempt 分层边界——重试、打断、阻塞各有归属。
②材料与记忆：手写常是"把历史字符串整个塞回去"；DSH 有来源、作用域、冻结与派生四件套——每个材料可回答"谁在什么条件下放进来"，历史不可变而表示可替换（压缩、spill）。
③动作与权限：手写常是"模型说啥就执行啥"；DSH 把提议与执行分离，准入、审批、守卫、沙箱四层各管一件事，成对审批事件可审计。
④事实与证据：手写的"成功"通常是一个布尔；DSH 的每个边界都有自己的事件与确认契约（append≠落盘、交接≠送达、安装≠生效），回放与投影让行为可复现、状态可查询。
⑤改进与协作：手写的改进靠个人记忆；DSH 的改进链是"事实→定位→产物→评价"，子代理与团队机制把同样的边界扩展到多成员（fork 只继承一致前缀、邮箱有确认与恢复、任务板有修订与依赖）。

**原理**：一句话概括——手写与 Harness 的差距不在功能清单，而在"不变量"：Harness 把"事实不可变、提议与执行分离、派生可重建、每个边界有确认契约"这些不变量固化在框架里，上层变化（换模型、加工具、拆任务）才有稳定的落点。这也是判断一个 Agent 系统成熟度的方法：不看它 demo 多流畅，看它崩溃、拒绝、超长、并发时，行为是否仍可解释。

**追问**：这些不变量手写就不能有吗？
**回答要点**：能，但每一项都是独立的工程负担（并发控制、审计、回放、迁移……），自研等于把维护这些不变量变成自己的长期成本；用框架则是接受契约换取保证——这正是教材第一章到第十章反复演示的取舍。
