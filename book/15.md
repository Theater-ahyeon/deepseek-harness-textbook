# 第 15 章｜桌面架构：Main、Renderer 与 Node Host

本章学习任务：理解 Main、Renderer 与 Node Host 的职责，追踪页面加载、Host 启动和客户端激活。

## 15.1 基本概念

桌面版通过 Electron 承载 Web 客户端。Renderer 运行页面，Main 管理窗口与应用生命周期，preload 向页面暴露受控桌面接口。Harness 后端服务运行在独立的 Node Host 子进程中，由 Main 管理其启动与退出。

进程是操作系统管理的一次程序运行，有自己的内存与生命周期。进程间通信（IPC）传递启动和退出等消息；聊天业务继续使用网页客户端的请求与持续流。HTTP 组织请求和响应，WebSocket 提供持续双向通道；它们与启动 IPC 各自解决不同问题。

启动时，Main 先加载本地页面，再等待 Host 返回服务地址与启动参数。页面显示等待状态，接收到启动参数后激活客户端。业务请求转发校验页面来源，并向 Host 请求补充认证信息。

普通主窗口关闭时隐藏窗口并保留后台运行；退出应用则进入任务中断检查和后端关闭流程。两类事件分别受桌面应用的生命周期管理。

## 15.2 沿一个任务看完整流程

桌面启动的可见顺序是：Main 导航到本地网页文档，随后启动后端准备；HostProcess 启动独立 Node 子进程，接收 ready 或 fatal 等消息。ready 携带服务 URL 与启动注入资料，同一页面据此继续激活客户端。

假设 200 毫秒看到等待界面，1000 毫秒业务可用，完整启动耗时应计为 1000 毫秒。页面出现但 Host 失败时排查子进程启动；Host 已 ready 但请求失败时排查转发和服务；业务状态已有变化但没有显示时排查客户端与视图。

主进程把页面业务路径转发到 Host，校验来源并适配认证。preload 提供目录选择等桌面接口，聊天请求使用 Web 客户端已有的通信方式。Main 管理窗口与后端生命周期，Node Host 运行 Harness 服务。

## 15.3 关键机制与设计取舍

### 三个环境与通信

![F15A：主进程、页面和宿主服务的边界](../figures/F15A.png)

图 15A 并列 Main、Renderer 和独立 Node Host。Main 管理窗口与启动，Renderer 显示 Web 产品，Node Host 运行模型、工具和 Session 服务。

### 先加载文档，再等服务准备

`reconcileBackend` 先导航到打包页面，再调用后端启动。窗口加载本地 Web 资源并等待启动注入，在 Host 准备就绪后直接基于当前文档激活服务。

`DesktopHostProcess.start` 创建 Node 子进程，建立 IPC 和输出管道，接收 ready 或 fatal 消息。ready 携带服务 URL 与 injections，也就是页面启动需要的服务地址等参数。已加载页面据此激活客户端，开始向 Host 发起业务请求。

桌面协议分别处理本地静态资源与业务请求。转发函数检查页面来源，映射目标路径和查询参数，并适配认证凭据。WebSocket 为页面与 Host 建立双向流通道。preload 通过受控接口提供目录选择、ready 等桌面能力。

### 进程与受控桥的基础

Main、Renderer 与 Node Host 各有内存和生命周期。preload 为 Renderer 暴露目录选择等桌面接口；文件工具由 Node Host 内的文件服务执行。

普通主窗口关闭会隐藏窗口并保留运行；退出应用进入任务中断检查和后端关闭流程。Main 分别处理这两个生命周期事件。

### 分析示例：页面出现与业务可用

教学启动时间线：0 ms 开始，200 ms 页面显示等待界面，900 ms Host 就绪，1000 ms 客户端可用。页面出现耗时 200 ms，业务可用耗时 1000 ms，中间等待区间为 800 ms。

复算记录：[C15 · 启动耗时](../examples/calculation-results.json)。

启动过程中，同一份页面先显示等待状态，收到 Host 的启动资料后再激活客户端。页面较早出现，让用户能看到启动进展；服务准备、启动注入和业务激活则继续在后台推进。

### 启动故障的分层定位

![F15B：同一页面等待注入后进入可用状态](../figures/F15B.png)

图 15B 按启动顺序展示窗口、打包页面、Host 和启动注入。页面先显示等待状态，收到 ready 资料后激活同一文档中的客户端。

桌面上的 README 总结仍经过 Agent 循环、工具执行和 Session 记录。Renderer 负责界面，Main 负责桌面生命周期，Node Host 中的文件服务执行读取；桌面壳将这三个环境连接起来。

### 常见误解

“页面加载完成就等于模型和工具可用”：Host 和客户端激活还有独立状态。

“所有业务都通过 preload IPC 直接进入 Agent”：已有 Web RPC 和流仍承担聊天过程。

“关闭窗口等于退出应用”：普通主窗口关闭时隐藏并保留运行；退出应用则进入任务中断检查和后端关闭流程。

## 15.4 源码研读

<a id="e15a"></a>

### E15A · 真正启动 Host 子进程的位置

阅读任务：这是 DesktopHostProcess.start 内部的子进程启动节选。this.node 是所选 Node 程序，runtimeDir 与 projectDir 是已准备的目录；本段观察入口、参数与通信管道。ready/fatal 消息处理属于后续路径。

#### 实现详解

桌面 Main 通过 DesktopHostProcess 管理 Harness 后端，start 在这里真正创建独立的 Node Host 子进程。它首先在 runtimeDir 下定位 dsh-desktop-host 包的 lib/index.js，再用 this.node 指定的 Node 程序执行入口。此前 start 会检查是否已有子进程，重复调用沿用现有的 readyPromise，避免再次启动同一个管理对象。

启动参数先放 Node 选项，再放 Host 入口和应用参数。--expose-internals 启用入口所需选项，配置 inspectPort 时才增加绑定 127.0.0.1 的调试参数。入口随后接收运行包目录、项目目录和主运行环境目录；主运行环境有显式设置时优先采用，否则使用约定路径。存在包管理器信息时，再追加 pnpm 和 Node 目录，供 Host 使用对应运行环境。

spawn 选项将项目目录设为工作目录，并通过 desktopNodeEnvironment 组织环境变量。标准输入设为 ignore，标准输出和错误输出设为 pipe，另开 IPC 通道。输出管道用于转发运行输出和保存失败诊断，IPC 用来接收 ready、fatal 与退出相关消息。这些设置将后端启动信息与普通进程输出分开处理。

spawn 返回子进程句柄后，管理器登记输出、消息和退出监听，继续等待 readyPromise。Host 启动完成时通过 ready 消息给出服务 URL 和页面注入资料，Main 才能使已经加载的等待页面激活业务客户端；fatal 或启动失败进入错误路径。以桌面 README 任务为例，页面先显示，后端就绪后才发出业务请求，模型与文件服务运行在这个 Node Host 中，Renderer 根据持续状态显示结果。

代码类型：**真实源码摘录**。证据编号 [E15A](../evidence-index.md#e15a)；下表的数字是原文件行号。

```ts
    const entry = join(this.runtimeDir, 'node_modules', '@deepseek-ai', 'dsh-desktop-host', 'lib', 'index.js')
    const child = spawn(this.node, [
      '--expose-internals',
      ...(this.inspectPort === undefined ? [] : [`--inspect=127.0.0.1:${String(this.inspectPort)}`]),
      entry,
      this.runtimeDir,
      this.projectDir,
      this.primaryRuntime ?? join(this.runtimeDir, '..', 'runtime', 'primary-runtime'),
      ...this.packageManager === undefined ? [] : [this.packageManager.pnpm, this.packageManager.nodeBin],
    ], {
      cwd: this.projectDir,
      env: desktopNodeEnvironment(this.node, undefined, this.environment),
      stdio: ['ignore', 'pipe', 'pipe', 'ipc'],
    })
```

## 15.5 理解检查与讲解问答

### 问题 1 · Main 与 Node Host 分别运行哪些功能？

讲解：Main 管理桌面窗口和后端生命周期，独立 Node Host 子进程运行 Harness 服务。

### 问题 2 · 等待页面出现是否等于业务已经可用？

讲解：等待页面表明 Renderer 已加载文档。业务可用还需要 Host 返回 ready，并完成客户端激活。

### 问题 3 · preload 是否直接承接所有聊天业务？

讲解：preload 暴露受控桌面接口，聊天业务使用 Web 客户端已有的请求与持续流通道。
