# 第 12 章｜MCP：外部工具与资源接入

本章学习任务：理解 stdio 与 Streamable HTTP 传输，追踪能力发现、注册代次、工具调用与资源读取。

## 12.1 基本概念

Model Context Protocol（MCP）规定客户端与服务端如何发现能力、交换请求和结果。客户端发起调用，服务端提供能力。协议规范通信与能力发现，存储、检索等具体操作由服务实现。

stdio 是 standard input/output 的缩写，通过子进程的标准输入和标准输出交换协议数据。标准输入接收外部数据，标准输出发送程序结果。HTTP（Hypertext Transfer Protocol，超文本传输协议）规定请求与响应的交换方式，URL 标识服务地址。Streamable HTTP 使用 URL 连接服务，支持跨网络访问。连接、能力发现、工具注册与调用完成分别对应不同状态。

来自不同服务器的工具通过名称包装进入同一注册表。包装层保存模型使用的公开名称与服务器原工具名的映射，模型调用公开名后，客户端据此向服务器发送原名。

在能力分类上，MCP 工具通过接收参数来执行操作，而资源接口则依据标识提取特定材料。客户端会独立发现并调用这两类能力。若要实现跨 Session 记忆，服务还要负责留存当前信息，以便在未来的 Session 里响应查询。

## 12.2 沿一个任务看完整流程

假设服务 A 采用 stdio 暴露 search 工具。客户端按配置启动进程建立连接，拉取完整工具列表，随后生成公开名称并更新注册代次。这里的代次用于标记这轮连接与工具注册的结果。模型请求公开名称后，调用先经过本地 ToolRuntime；执行包装随即换回服务器原工具名，把参数、取消信号和超时配置发送给远端执行。

服务 B 使用 Streamable HTTP 时，客户端连接其 URL；服务 A 则由本机子进程承载 stdio 通信。两者发现的工具都进入本地 ToolRuntime。更新工具列表先准备完整定义，准备失败保留旧注册；进入交换阶段后若新注册失败，客户端撤销本轮已注册项，使该服务器在本地没有工具注册。

远端工具返回内容后，本地包装逻辑依据输出契约整理格式并交给 Session。资源能力则依靠独立接口发现和读取。检索算法依赖服务端实现：子字符串查询负责匹配原文有无检索词，向量检索依据 embedding 相似度来提取材料。

## 12.3 关键机制与设计取舍

### 外部工具复用原工具链

![F12A：发现远端工具后，包装成现有工具能力](../figures/F12A.png)

图 12A 从建立 MCP 连接和发现工具起步，经过公开名称包装与本地注册，随后过渡到模型调用与远端执行。本地 ToolRuntime 继续负责处理准入判断、取消信号以及执行结果。

### 连接、发现与代次交换

客户端按配置建立连接，并同步该连接代次的工具列表。代次标识本轮连接及其注册结果。同步先获取完整列表并构建所有定义，期间保留旧注册；准备成功后撤销旧注册，再逐项注册新定义。若新注册冲突，代码撤销本轮已注册项，使该服务器在本地留下零项工具注册；严格启动同步继续抛错，普通同步记录错误并返回空注册表。

工具公开名统一使用 `mcp__服务名__原工具名` 的拼接形式。对于合法短名称直接组合，遇到非法字符或长度越界时，程序引入规范化与哈希处理。哈希将输入转换为较短标识，而执行包装始终留存服务器的原工具名，以便向远端发起调用。

包装定义把远端的参数 schema、描述说明及执行函数衔接至本地 ToolRuntime。模型触发对公开名的调用时，参数先走过本地准入与执行链，接着由包装层按服务器原名发送远端请求。得到的模型文本和结构化内容依据输出契约规范格式；除此之外，资源插件提供独立的通道来负责资源的发现与读取。

### 连接与知识能力的基础区别

客户端向外发送请求，服务端提供可用的协议能力，远程调用则在本地进程或跨网络通道间传输参数和执行结果。MCP 负责规范这层基础交互协议。RAG（Retrieval-Augmented Generation，检索增强生成）则先提取关联材料，接着把内容补充进模型上下文，比如先检索工程文档再生成摘要总结。两者目标明确：协议接入负责通信链路，检索生成处理信息组织方式。

具体 Memory 服务的底层存储与查询逻辑，决定了其是否具备 embedding、语义检索和跨 Session 记忆功能。第 8 章提到过，embedding 把文字转换成用于衡量相似度的向量。当前项目的 Memory MCP 指南包含可选第三方服务的接入步骤，里面的 Reference Memory 依靠子字符串完成查询；这些具体能力都要通过相应的服务配置开启。

### 分析示例：分项检查服务能力

当前教学服务已完成连接，并获取到一项检索工具，但它缺乏资源能力声明，跨 Session 记忆功能也未经证实。对照四项验收指标填写如下：连接通过、工具发现通过、资源读取未证实、跨 Session 记忆未证实。

在后续使用该工具之前，仍需测试实际调用结果、调用许可状态以及数据质量。走协议接入的优势在于复用现有成熟链路，相应的代价则增加了外部服务可用性、网络超时、版本更新与返回契约带来的维护负担。

### 回到项目资料任务

![F12B：连接、工具、资源与记忆分别需要证据](../figures/F12B.png)

图 12B 按能力分列当前状态：连接与工具发现已完成，资源能力目前未声明，跨 Session 存储与查询还未接入。每栏各自对应一组独立请求。

处理服务发现失败时，除观察页面连接指示灯外，排查重点在于当前连接代次和已注册定义。定位远端调用错误需要追踪包装执行与服务器返回的数据，将其简单当成本地文件权限错误会偏离排查方向。

### 常见误解

“用了 MCP 就做了 RAG”：MCP 规定能力发现与通信方式，RAG 将检索所得材料加入模型上下文。协议接入与检索生成方法分别处理通信和信息组织。

“服务连上就知道它的全部资料”：建立连接仅打通通道，提取内容要依靠具体发现和读取动作。

Memory 服务的各项能力取决于底层存储、查询算法和启用配置。比如向量检索需要服务侧提供对应的向量表示与搜索代码。

## 12.4 源码研读

### E12A · stdio 与 HTTP 的不同执行边界

阅读任务：以下是 createTransport 完整代码。config 已完成配置解析，transport 字段负责指定连接方式；请留意执行命令与 URL 最后交给了谁来处理。

#### 实现详解

createTransport 将解析后的 MCP 配置转换为客户端需要的传输对象。transport 字段选择构造分支，两种实现都遵循 Transport 接口，后续客户端通过同一连接流程完成握手、能力发现与工具同步。构造阶段建立连接参数，实际连接由后续客户端逻辑推进。

stdio 分支构造 MCP SDK 的 StdioClientTransport，传入 command、args、cwd 和环境变量。SDK 在传输启动时创建服务端子进程，并通过标准输入输出交换协议数据。command 指定可执行命令，args 提供参数，cwd 指定工作目录。buildChildEnv 先取得按项目规则清理后的父环境，再以显式 env 覆盖同名变量；环境清理规则由项目复用，实际 spawn 由 SDK 执行。

Streamable HTTP 分支把 config.url 解析为 URL 对象，将 headers 放入 HTTP 请求初始化设置，再构造传输。客户端通过服务地址访问 MCP Server，服务端进程由其部署方式管理。URL 解析失败会使构造报错，网络连接与协议错误则在后续连接或请求中处理。请求头可携带服务需要的认证资料。

本机检索服务以命令启动时使用 stdio 配置，已有网络服务提供 URL 时使用 Streamable HTTP 配置。客户端取得传输后连接服务、发现 search 等工具，并包装成 ToolRuntime 注册项。模型调用公开名仍经过本地准入与执行包装，随后发送服务请求。传输选择确定进程或网络通信边界，能力注册与每次调用沿客户端主流程完成。

代码类型：**真实源码摘录**。证据编号 [E12A](../evidence-index.md#e12a)；下表的数字是原文件行号。

```ts
export function createTransport(config: Config): Transport {
  switch (config.transport) {
    case 'stdio':
      return new StdioClientTransport({
        command: config.command,
        args: config.args,
        env: buildChildEnv(config.env),
        cwd: config.cwd,
      })
    case 'streamable-http':
      return new StreamableHTTPClientTransport(
        new URL(config.url),
        { requestInit: { headers: config.headers } },
      )
  }
}
```

## 12.5 理解检查与讲解问答

### 问题 1 · 所有 MCP 服务都在本机子进程里运行吗？

讲解：stdio 类型的服务运行在客户端启动的本机子进程内；Streamable HTTP 则利用 URL 建立服务连接，使得程序有能力访问远端服务器。

### 问题 2 · 工具列表更新失败，是否应该先清空旧工具？

讲解：同一连接更新工具列表时，先完整发现并构造新定义，准备失败保留旧注册。准备成功后才撤销旧注册；若注册新列表时发生冲突，代码清理本轮已注册项，该服务器此时没有本地工具注册。

### 问题 3 · 发现 search 是否证明已做语义检索？

讲解：MCP 专职传递工具说明、入参及调用结果。search 依托的检索机制则交由服务器编写，包括关键词查找、数据库读取或向量检索；判断实际的查询算法需参考服务器的内部实现。
