# 第 12 章｜MCP：外部工具与资源接入

本章学习任务：理解 stdio 与 Streamable HTTP 传输，追踪能力发现、注册代次、工具调用与资源读取。

## 12.1 基本概念

Model Context Protocol（MCP）规定客户端怎样与服务端发现能力并交换请求和结果。客户端发起调用，服务端提供能力。协议处理通信与能力发现，具体服务实现存储、检索或其他动作。

stdio 是 standard input/output 的缩写，通过子进程的标准输入和标准输出传递协议数据。标准输入接收外部数据，标准输出发送程序结果。HTTP（Hypertext Transfer Protocol，超文本传输协议）规定请求与响应的交换方式，URL 标识服务地址。Streamable HTTP 使用服务 URL，支持跨网络连接。连接、能力发现、工具注册和调用完成分别对应不同状态。

名称包装让来自不同服务器的工具能进入同一注册表。公开名称和服务器原工具名可能不同；执行包装保存二者的对应关系，因此模型调用公开名以后，客户端仍向服务器发送原名。

MCP 工具接收参数并执行操作，资源接口按标识读取材料。客户端分别发现并调用这些能力。跨 Session 记忆还需要服务保存信息，并在后续 Session 中提供相应查询。

## 12.2 沿一个任务看完整流程

假设服务 A 通过 stdio 提供 search 工具。客户端启动配置指定的进程、建立连接、获取完整工具列表，再构造公开名称并更新注册代次。代次标识本次连接及其工具注册结果。模型调用公开名称后，请求经过本地 ToolRuntime；执行包装使用服务器原工具名，将参数、取消信号与超时配置传入远端调用。

服务 B 使用 Streamable HTTP 时，客户端连接它的 URL；服务 A 的 stdio 则由本机子进程承载。两者发现的工具都接入本地 ToolRuntime。更新时先准备完整定义，准备失败保留旧注册；开始交换后若新注册失败，客户端撤销本轮已注册项，结果是该服务器没有工具注册。

远端工具返回内容后，本地包装按输出契约整理，再交给 Session。资源能力通过独立接口发现和读取。检索算法由服务器实现：子字符串查询匹配原文是否含查询词，向量检索则按 embedding 相似度选择材料。

## 12.3 关键机制与设计取舍

### 外部工具复用原工具链

![F12A：发现远端工具后，包装成现有工具能力](../figures/F12A.png)

图 12A 从 MCP 连接与工具发现开始，经过公开名称包装和本地注册，再进入模型调用与远端执行。本地 ToolRuntime 继续处理准入、取消和结果。

### 连接、发现与代次交换

MCP 客户端按配置建立连接，并同步该连接代次的工具列表。代次标识一轮连接及其注册结果。同步分两阶段：先获取完整列表并构建所有定义，此时保留旧注册；准备成功后撤销旧注册，再逐项注册新定义。新注册发生冲突时，代码撤销本轮已注册项，使该服务器留下零项工具；严格启动同步继续抛错，普通同步记录错误并返回空注册表。

工具公开名采用 `mcp__服务名__原工具名` 的命名形式。简单有效名称直接拼接，非法字符和过长名称经过规范化与哈希处理。哈希把输入映射成较短标识，执行包装仍保存服务器原名，用于发送远端调用。

包装定义将远端参数 schema、说明和执行函数接到 ToolRuntime。模型调用公开名，参数经过本地准入与执行链，再由包装层向服务器原名发起调用。返回的模型文本与结构化内容按输出契约处理；资源插件另行提供资源发现和读取。

### 连接与知识能力的基础区别

客户端发起请求，服务端提供协议能力，远程调用在进程或网络之间传递参数与结果。MCP 规定这层交互协议。RAG（Retrieval-Augmented Generation，检索增强生成）先检索相关材料，再将材料加入模型上下文，例如检索项目文档后生成总结。协议接入和检索生成分别解决通信与信息组织问题。

Memory 服务的存储与查询实现决定是否支持 embedding、语义检索和跨 Session 记忆。embedding 将文本编码为用于相似度比较的向量，第 8 章已有介绍。本项目的 Memory MCP 指南提供可选第三方服务的接入方式，其中 Reference Memory 采用子字符串查询；相关能力通过对应服务配置启用。

### 分析示例：分项检查服务能力

教学服务已经建立连接，发现了一个检索工具，但没有声明资源能力，也没有验证跨 Session 记忆。四项验收应填：连接通过、工具发现通过、资源读取未证实、跨 Session 记忆未证实。

继续使用该工具前，还要检查一次实际调用结果、调用许可与结果质量。以协议接入可以复用成熟链路，代价是多了外部可用性、超时、版本和返回契约问题。

### 回到项目资料任务

![F12B：连接、工具、资源与记忆分别需要证据](../figures/F12B.png)

图 12B 按能力分别列状态：连接与工具发现已经完成，资源能力尚未声明，跨 Session 存储与查询尚未接入。每一栏对应一组独立的请求。

服务发现失败时，检查当前连接代次和已注册定义，而不只看页面的连接指示灯。远端调用失败时，则要查包装执行与服务器返回，不能自动归类为本地文件权限错误。

### 常见误解

“用了 MCP 就做了 RAG”：协议接入与检索生成方法是不同层次。

“服务连上就知道它的全部资料”：需要能力发现和具体读取；连接本身不提供全文。

Memory 服务的能力需要由存储实现、查询算法和启用配置确定。向量检索依赖相应的向量表示与检索实现。

### E12A · stdio 与 HTTP 的不同执行边界

阅读任务：这是 createTransport 完整函数。config 已通过配置解析，transport 决定选哪一种连接；重点是命令与 URL 分别交给谁处理。

代码类型：**真实源码摘录**。证据编号 [E12A](../evidence-index.md#e12a)；下表的数字是原文件行号。

```ts
export function createTransport(config: Config): Transport {
  switch (config.transport) {
    case 'stdio':
      return new StdioClientTransport({
        command: config.command,
        args: config.args,
        env: buildChildEnv(config.env),
        cwd: config.cwd,
      })
    case 'streamable-http':
      return new StreamableHTTPClientTransport(
        new URL(config.url),
        { requestInit: { headers: config.headers } },
      )
  }
}
```

## 12.5 理解检查与讲解问答

### 问题 1 · 所有 MCP 服务都在本机子进程里运行吗？

讲解：stdio 服务由客户端启动的子进程承载；Streamable HTTP 通过 URL 连接服务，可以访问远端服务器。

### 问题 2 · 工具列表更新失败，是否应该先清空旧工具？

讲解：同一连接更新工具列表时，先完整发现并构造新定义，准备失败保留旧注册。准备完成后才撤销旧注册；如果注册新列表发生冲突，代码清掉本轮已注册项，该服务器此时没有工具。

### 问题 3 · 发现 search 是否证明已做语义检索？

讲解：MCP 传输工具说明、参数和调用结果。search 背后的检索方法由服务器实现，可以是关键词查询、数据库查询或向量检索；要沿服务器的实现确定具体算法。
