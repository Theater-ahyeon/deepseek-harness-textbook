# 第 10 章｜插件框架与运行配置：这些部件怎样装成一个应用

本章学习任务：从配置条目说明插件怎样装配、怎样获取所需服务；区别 profile、条目修改与运行实例，并定位热更新的边界。

## 10.1 基本概念

插件是一份可装入应用的能力实现，例如注册文件工具的模块。配置给出本次采用的参数，profile 选择整组插件及其设置。启动程序按配置装入插件，插件再注册服务、工具和监听器。

依赖指一个部件运行前需要另一项能力，例如文件工具需要工具注册表与文件服务。依赖注入让框架提供这些能力，而不是让每个插件自行创建一份。Context 是 Cordis 用于访问当前可用服务与登记资源的对象。注册和资源清理属于插件生命周期：装入、运行、卸载各自有动作。

条目是一项插件及其设置的记录，补丁描述这次怎样修改这些记录。配置合成规则决定补丁怎样作用到原条目。注册表保存名称与实现等对应关系，让使用者在需要时找到能力。

启动入口先读取运行选择与配置层，再合成条目、加载插件，满足依赖后执行插件的装入函数。函数执行期间注册工具，不表示文件已经读取。条目补丁按 id 定位插件，对补丁中的每个条目字段直接赋值。

热重载在运行时替换符合条件的部件。内部模块可以局部刷新，外部依赖变化则走完整重载路径。Cordis 在卸载时调用已登记的清理函数，例如撤销工具注册或事件监听；第 19 章展开资源登记与释放的机制。

## 10.2 沿一个任务看完整流程

以文件工具插件为例：配置给出读取上限，启动程序把合成后的条目交给加载器；依赖可用以后执行 apply。apply 检查参数，再注册 read 等工具。此时注册表变了，但磁盘文件没有因注册而被读取。用户任务中出现合法调用，才进入执行函数。

配置层先展平成有序补丁列表。applyEntryPatches 按 id 找条目，再用补丁值覆盖对应字段；config 也是一个整体字段。insert 可以向顶层或指定分组加入条目，新条目随即进入 id 索引，供后续补丁修改。缺少目标、目标不是分组或 name 校验不匹配时，函数记录警告并跳过该补丁。

卸载时，框架处理登记的资源释放。热重载还需分析模块依赖：可替换的内部模块走局部处理，外部依赖变化会设置完整重载并调用退出路径。局部替换先释放旧实例的登记资源，再装入新实例；完整重载交给退出和重启路径处理。

## 10.3 关键机制与设计取舍

### 配置层怎样汇合

![F10A：配置层按顺序组合为插件树](../figures/F10A.png)

图 10A 按配置应用顺序排列：bundle、profile patch、用户目录 patch、命令行 patch。最终条目交给加载器，满足依赖的插件完成挂载。

### 启动到挂载的主链

CLI 是 Command-Line Interface，即通过终端命令与选项操作程序的入口。它解析启动参数，profile 模式进入 `runProfile`。运行器准备环境，读取组合包和有序补丁，得到 Cordis 配置条目。每个条目保存插件及其设置；多个条目按分组组织成应用树。`boot` 将树中的插件挂载到应用，插件由此提供服务、工具和事件监听。

消费者通过 Context 访问服务，例如文件工具使用文件服务，循环使用模型服务。Provider 实现服务接口，profile 决定挂载哪一份实现。查看应用树，可以确定当前运行使用哪些包及其配置。

官方架构中的 base 是多种 profile 的共享第一层，而 `sdk-minimal` 是例外：它的组合包拥有完整显式配置树，不应用 base。不同 profile 对热重载的设置也不同。热重载在可局部替换时使相应变化生效；需要完整重载的情形仍走退出与重新启动路径。

### 依赖注入与生命周期

依赖注入（dependency injection）让插件声明所需服务，再由配置环境提供。框架在当前作用域解析服务；依赖未满足时，实例等待可用环境，服务注册冲突则进入错误处理。作用域决定插件树中哪些位置可以获取这项服务。

插件从安装到卸载的存续期间称为生命周期。注册产生的副作用通常随插件卸载而撤销，例如移除事件监听或能力声明。事件监听是插件为某类事件登记的响应。撤销这项注册后，插件就不再接收相应通知；插件已发出的网络请求和已写入的文件仍由各自服务处理后续状态。

### 分析示例：覆盖整个 config

设一个插件条目的 config 是 `{timeout: 100, limit: 20}`，后续补丁给同一 id 设置 `{timeout: 300}`。applyEntryPatches 直接替换 config，结果只剩 timeout: 300。

加载插件时，配置 schema 再为缺省字段应用默认值。若要显式保留 limit: 20，后续 config 中也应写出它。条目覆盖和插件配置解析是两个连续阶段。

### Provider 替换的含义

![F10B：消费者依赖服务契约，配置选择 Provider](../figures/F10B.png)

图 10B 的三栏是消费者、配置与作用域、Provider。read 调用文件服务接口，配置选出具体实现，Provider 负责路径、读取、取消和错误处理。

读取 README 的 profile 需要装入循环、工具、文件服务和模型 Provider。所选模型路由与工具作用域继续决定本次可用能力。Skill、压缩和 MCP 也按当前配置树启用。

### 常见误解

“包安装了，能力就启用了”：安装与挂载是不同动作，当前 profile 决定是否进入应用树。

“所有 profile 都带 base”：`sdk-minimal` 的明确例外推翻这一概括。

“卸载插件会撤销它做过的一切”：卸载调用已登记的释放函数；文件写入和远端请求由各自服务处理后续状态。

### E10A · 配置层交给条目补丁规则

阅读任务：这是 composeEntries 完整函数。layers 是启动阶段获取的配置层集合，warn 是可替换的警告回调；重点看展平、复制和真正执行合成规则的位置。

代码类型：**真实源码摘录**。证据编号 [E10A](../evidence-index.md#e10a)；下表的数字是原文件行号。

```ts
export function composeEntries(
  layers: readonly PatchOptions[][], warn: (message: string) => void = () => {},
): EntryOptions[] {
  return applyEntryPatches([], structuredClone(layers.flat()), (message: string, ...args: unknown[]) => {
    let index = 0
    warn(message.replace(/%C/g, () => JSON.stringify(args[index++])))
  })
}
```

| 原文件行号 | 写法 | 在这段流程中的作用 |
| --- | --- | --- |
| 731 | export 与 function | 公开配置合成操作供启动程序调用。 |
| 732 | readonly 嵌套数组与默认箭头函数 | 接收多层补丁，未给警告处理时采用空操作。 |
| 733 | 返回类型与函数体开始 | 合成结果是 EntryOptions 数组。 |
| 734 | flat、structuredClone 与回调 | 展平并复制层数据，再交给条目补丁函数，以空条目集为起点。 |
| 735 | let 初始化计数 | 当前警告格式替换从第 0 个附加参数开始。 |
| 736 | replace 正则与 JSON.stringify | 将警告中的占位符换成参数的可读表示，再通知 warn。 |
| 737 | 结束回调与补丁调用 | applyEntryPatches 的结果作为本函数结果返回。 |
| 738 | 结束函数 | 加载器随后依据合成条目装配插件。 |

## 10.5 理解检查与讲解问答

### 问题 1 · 插件装入时注册 read，是否已经发生读取？

讲解：没有。装入使工具可用，后来具体调用才进入执行体。

### 问题 2 · 热重载是否保证永远不重启？

讲解：内部模块满足局部替换条件时走热替换；外部依赖变化触发 fullReload，随后通过 loader.exit 退出，交给重启路径重新加载。

### 问题 3 · 配置覆盖能否按任意深合并理解？

讲解：applyEntryPatches 对条目字段直接赋值。config 是一个整体字段，后面的 config 会替换前面的对象；加载插件时，schema 再为缺省字段应用默认值。
