# 第 10 章｜插件装配、运行配置与热重载

本章学习任务：理解配置条目、profile 与依赖注入，分析插件装配、字段覆盖和热重载。

## 10.1 基本概念

插件是一份装入应用的能力实现，例如负责注册文件工具的模块。配置给出当前所需的参数，profile 选择整组插件和相关设置。启动程序依配置加载插件，插件随后注册服务、工具和监听器。

依赖指插件运行必须的外部能力，比如文件工具需要工具注册表和文件服务。框架利用依赖注入把这些服务交接给插件。Cordis 提供 Context 接口对象用以访问服务及登记资源。插件经历装入、运行和卸载的生命周期，各类注册与释放操作在对应阶段执行。

配置条目保存插件身份及其设置，补丁则标明对条目字段的修改。配置合成过程依序处理各层补丁，产出加载器使用的条目树。注册表记录名称与实现的关联，方便消费方查找对应能力。

启动入口先读取运行选项与配置层，再合成条目、加载插件，满足依赖后执行装入函数。文件工具在装入时注册 read，具体文件读取由后续任务中的工具调用触发。条目补丁按 id 定位插件，对补丁给出的字段直接赋值。

热重载可在运行时替换符合条件的组件。内部模块支持局部刷新，当外部依赖发生变化时，系统进入完整重载流程。Cordis 卸载插件时会调用预先登记的清理函数，像撤销工具注册或清除事件监听；资源登记与释放细节在第 19 章讲解。

## 10.2 沿一个任务看完整流程

以文件工具插件为例：配置里设定读取上限，启动程序把合成完成的条目传递给加载器；各项依赖就绪后程序执行 apply 函数。apply 会检验参数，并把 read 工具注册到位，从而更新注册表。真实的文件读取动作，等到用户任务发起有效调用并进入内部执行函数时发生。

配置层先展平为有序补丁列表。applyEntryPatches 按 id 定位目标，再用补丁值覆盖对应字段，config 也作为整体字段替换。带有 insert 的补丁向顶层或指定分组添加条目，新条目随即进入 id 索引，供后续补丁修改。目标不存在、插入目标不是分组或 name 校验不匹配时，函数记录警告并跳过相应补丁。

插件卸载时，框架接手处理已登记的资源释放。热重载还需检查模块依赖关系：符合条件的内部模块进入局部处理，外部依赖变动引发完整重载，调用退出逻辑。局部替换会先释放旧实例占用的登记资源，再把新实例装入环境；完整重载则交由退出与重启路径接管后续处理。

## 10.3 关键机制与设计取舍

### 配置层怎样汇合

![F10A：配置层按顺序组合为插件树](../figures/F10A.png)

图 10A 展示了配置的应用顺序：先是 bundle，接着是 profile patch、用户目录 patch，最后应用命令行 patch。合成后的最终条目会交付给加载器，依赖条件满足的插件由此完成挂载过程。

### 启动到挂载的主链

CLI（Command-Line Interface）是通过终端命令与选项操作程序的入口。CLI 解析启动参数，profile 模式进入 `runProfile`。运行器准备环境，读取组合包与有序补丁，生成 Cordis 配置条目。条目保存插件及其设置，并按分组构成应用树；`boot` 挂载树中的插件，由它们提供服务、工具和事件监听。

消费方通过 Context 访问服务，例如文件工具使用文件服务，循环使用模型服务。Provider 实现服务接口，当前 profile 选择挂载哪份实现。应用树记录当前运行所用的包及其配置。

在官方架构里，base 作为多数 profile 共享的底层配置，但 `sdk-minimal` 是个例外：该组合包自带一套完整的显式配置树，无须应用 base。各类 profile 对热重载的处理设置各有差异。当情况符合局部替换条件时，热重载直接应用相关变更；若必须完整重载，程序依然遵循退出应用并重新启动的路径运行。

### 依赖注入与生命周期

依赖注入（dependency injection）允许插件声明所需服务，由配置环境提供具体实现。框架在当前作用域解析服务；依赖未满足时，实例等待服务可用，服务注册冲突则进入错误处理。作用域决定插件树中哪些位置能够获取这项服务。

插件从最初安装一直到卸载的这段存续时间即为生命周期。执行注册所留下的副作用一般随着插件卸载被撤销，就像移除原有的事件监听或者能力声明。事件监听代表插件为特定事件登记的响应动作。一旦撤销这项注册，插件就不再接收相关的事件通知；然而插件此前发出的网络请求及已经写入磁盘的文件操作，依然交给各自对应的服务去管理后续状态。

### 分析示例：覆盖整个 config

假设某插件条目的 config 值为 `{timeout: 100, limit: 20}`，后方的补丁对同一个 id 写入 `{timeout: 300}`。因为 applyEntryPatches 会整体替换 config 字段，合并的结果仅保留 timeout: 300。

等到加载插件的时候，程序再利用配置的 schema 给缺失的字段填补默认值。如果希望在新配置里明确保留 limit: 20，那么后续的 config 对象中也得写上这个属性。因此，补丁替换条目字段与插件按 schema 解析配置，属于两个先后衔接的连续阶段。

### Provider 替换的含义

![F10B：消费者依赖服务契约，配置选择 Provider](../figures/F10B.png)

图 10B 展示了消费者、配置与作用域、Provider 三栏。read 操作调用文件服务接口，配置为其挑选具体的实现，随后该 Provider 负责处理目标路径、读取操作、动作取消以及错误上报。

执行读取 README 的 profile 时，程序需装入循环、工具、文件服务和模型对应的 Provider。选定的模型路由与工具作用域进一步圈定了本次可用的能力。Skill 模块、文本压缩以及 MCP 同样根据当前的配置树启用。

### 常见误解

“包安装了，能力就启用了”：包安装和实例挂载是不同的动作，是否进入应用树由当前 profile 决定。

base 是多数 profile 的共享配置层；`sdk-minimal` 使用独立的显式配置树。

“卸载插件会撤销它做过的一切”：插件卸载仅调用已登记的释放函数；已经触发的文件写入和远端请求，交由各自的服务负责处理后续状态。

## 10.4 源码研读

<a id="e10a"></a>

### E10A · 配置层与条目补丁的合成

阅读任务：这是 composeEntries 的完整函数。参数 layers 为启动阶段收集的配置层集合，warn 是允许替换的警告回调；请重点关注执行展平、数据复制以及真正调用条目合成规则的具体位置。

#### 实现详解

composeEntries 将启动阶段收集到的配置层合成为加载器使用的插件条目列表。layers 外层数组规定应用先后顺序，内层数组存放该层的补丁。此函数以空条目集为起点，把全部层展平为单一的有序补丁序列，交由 applyEntryPatches 逐个执行。基础组合包先提供初始条目，随后由 profile、用户与命令行的补丁沿此顺序完成修改。

层数据展开后先执行 structuredClone 提取一份独立副本。由于处理补丁需要构建条目树、更新 id 索引以及改写条目字段，这份副本能防止处理过程影响调用方保存的原配置层数据。具体合成规则由 applyEntryPatches 落实：插入操作直接创建条目，修改操作依照 id 找到已有条目，然后对指出的字段执行赋值。当发现目标缺失、分组不匹配或 name 验证没通过时，该处理器会发出警告并跳过这条补丁。

字段覆盖包含整个 config。前层保存 timeout=100、limit=20，后层给同一 id 的 config 设置 timeout=300，合成结果只保留 timeout=300。插件加载时再通过自身 schema 处理缺省字段并应用默认值。条目字段覆盖与插件参数解析因此发生在两个连续阶段。

函数内部的回调把警告消息里的 %C 占位符逐个换成附加参数的 JSON 文本表示，再交付给调用方的 warn 处理；若未提供 warn 则使用空操作。函数最后返回一份 EntryOptions 数组，加载器凭此挂载相应插件，并在依赖条件齐备后触发插件的 apply。以文件工具为例，条目合成决定了工具是否启用及其读取上限，挂载阶段完成 read 的注册，真正的文件操作等待后续任务中的调用执行。

代码类型：**真实源码摘录**。证据编号 [E10A](../evidence-index.md#e10a)；下表的数字是原文件行号。

```ts
export function composeEntries(
  layers: readonly PatchOptions[][], warn: (message: string) => void = () => {},
): EntryOptions[] {
  return applyEntryPatches([], structuredClone(layers.flat()), (message: string, ...args: unknown[]) => {
    let index = 0
    warn(message.replace(/%C/g, () => JSON.stringify(args[index++])))
  })
}
```

| 732 | readonly 嵌套数组与默认箭头函数 | 接收多层补丁，未给警告处理时采用空操作。 |
| 733 | 返回类型与函数体开始 | 合成结果是 EntryOptions 数组。 |

执行推演：程序先将多层条目展平并复制副本，随后交给 applyEntryPatches 处理。它根据 id 定位目标对象并直接覆盖指定字段；如果目标相同，排在后层的补丁值覆盖前层值。

## 10.5 理解检查与讲解问答

### 问题 1 · 插件装入时注册 read，是否已经发生读取？

讲解：没有发生。装入仅让工具可用，后来的实际调用才进入执行体。

### 问题 2 · 热重载是否保证永远不重启？

讲解：只有当内部模块符合局部替换条件时会执行热替换；一旦外部依赖发生变化便触发 fullReload，然后调用 loader.exit 退出当前应用，交由重新启动路径完成加载。

### 问题 3 · 配置覆盖能否按任意深合并理解？

讲解：applyEntryPatches 对目标条目字段执行直接赋值。config 被视为整体字段，后续 config 对象会覆盖前面的；直到加载插件时，对应的 schema 才会给缺省字段提供默认值。
