# 第 2 章｜读懂代码：类型与异步等待

本章学习任务：认出值、对象、函数和类型的基本写法；解释一次 await 等待的结果，并区分注册回调、调用回调和后台完成。

## 02.1 基本概念

先把程序里的信息和动作拆开。变量是给一项值取的名字，例如 `path` 保存路径文字。字符串是文字值；数字可以表示起始行号；布尔值只有真和假。对象把相关信息放在一起，例如一份读取请求同时保存路径、起始行和行数。属性是对象中的一项信息，`request.content` 表示请求的内容属性。数组按位置保存多项值，例如多行文本；位置通常从 0 开始，文件行号却常从 1 开始，两个口径不能混用。

函数把一组步骤包装成可以调用的操作。参数是调用者交给函数的值，返回值是函数返回的值。方法是属于某个对象的函数；`agent.followup(message)` 表示让这个 Agent 的方法处理消息。类描述一类对象的结构和操作，实际创建出来的对象叫实例。接口和类型说明规定数据形状，例如路径应是字符串。文件是否存在，要等文件服务访问目标时检查。

TypeScript 在 JavaScript 的写法上增加类型说明。`const` 固定变量绑定，`let` 允许重新赋值；对象内部仍可能变化。冒号后面通常是类型，问号表示可缺省，`return` 把值返回调用者，`throw` 使当前路径失败。花括号既可能围住对象，也可能围住一组语句，要看它的位置。模块是单独组织代码的文件；`import` 引入别的模块，`export` 让别处能够使用本模块的名称。

Promise 表示一项异步操作的结果，可以处于等待中、成功或失败状态。`async` 方法返回 Promise，`await` 暂停这个方法的后续部分，等待该结果；其他工作可以继续推进。进程是操作系统管理的一次程序运行，线程是进程内一条执行指令的路径。等待期间，JavaScript 运行时可以执行其他已经就绪的工作。并发是多项工作可以交错推进，并行是同一时刻用多个执行资源处理多项工作；多个操作怎样交错，取决于它们的启动与等待顺序。回调是交给别处、等特定时机再调用的函数，例如收到事件后更新记录。以后看到 `() => ...`，先问谁会在什么时候调用它，而不是把它当成已经执行的结果。

JavaScript 是运行这些步骤的语言；TypeScript 的类型检查帮助在执行前发现写法与数据形状的问题。程序真正运行时，输入是否合法、资源是否可用仍要由实际代码检查。运行时的事件循环会处理已准备的工作并恢复后续执行；等待外部读取时，当前方法暂停，其他已准备工作仍可推进。

### 语法导航：从已讲过的数据与动作认写法

阅读源码时，可以用下表查询常见写法；每段节选还配有逐行解释。

| 写法 | 语言含义 | 本项目里的阅读用处 |
| --- | --- | --- |
| const / let | 固定绑定／可重新赋值的绑定 | 保存结果或推进游标；固定绑定不冻结对象内部 |
| undefined / null | 未提供的值／显式表示无值 | 区分缺省配置与实际结果 |
| this / new | 当前对象／创建实例 | 访问所属服务，或建立错误与传输对象 |
| :、?、void | 类型说明、可缺省、不使用返回值的类型约定 | 阅读参数形状、可选字段与函数签名 |
| Promise 与 await | 将来结果与等待结果 | 找等待的是接纳、读取还是其他边界 |
| if / else / switch | 按条件或类别选择路径 | 分清允许、拒绝和不同后端 |

| && / \|\| | 短路求值：&& 遇到假值停止，\|\| 遇到真值停止，返回停下时的操作数 | 阅读复合条件与取值表达式，确认右侧是否执行 |
| ?. / ?? | 对缺省对象安全访问／缺省时采用另值 | 读取可选 Agent、选择配置默认值 |
| () => ... | 把函数作为值写出 | 问谁以后调用回调，区别定义和执行 |
| {...对象} | 将已有对象属性放入新对象 | 保留已有决定，再替换 messages |
| {a,b}=对象 | 解构取出指定属性 | 将目标和文件信息分开命名 |
| [...数组] / ...数组 | 复制数组成员／展开成员 | 返回新视图或组合领取结果 |
| for...of | 逐项取出数组等集合的成员 | 对领取消息逐项发通知 |
| map / filter / some | 转换每项／保留符合条件项／检查是否有符合项 | 构造卡片行、提取工具提议、检测重复材料 |
| slice / toSpliced | 取前缀等子区间／建立修改后的新数组 | 继承事件或插入指令，不当然生成摘要 |
| try / catch / finally | 尝试路径／处理失败／离开时收尾 | 跟踪错误怎样返回和资源怎样释放 |

| 泛型 <T>、unknown、as | T 为具体类型留位置，例如同一容器可保存文字或事件；unknown 要求先确认值的种类；as 向类型检查器声明自己的判断 | 用类型组织事件；as 不会替程序验证真实输入 |
| readonly / private | TypeScript 的只读约束／类成员访问约束，主要用于类型检查 | 阅读代码中的写入与访问约定；运行时私有字段使用 # 名称 |
| using | 作用域结束时调用资源释放协议 | 读取附件绑定等有资源生命周期的代码 |

遇到单独一行的右括号，先看它关闭的是对象、函数、条件还是调用。逐行表会标出结构关系；沿函数的参数、调用和返回位置继续阅读，就能把这些写法接回实际流程。

## 02.2 沿一个任务看完整流程

`await prompt(...)` 等待提交回执。接纳方法校验请求内容，把消息交给 Agent，再返回接纳对象。调用方拿到回执后可以继续工作；Agent 驱动继续处理任务，最终总结通过持续观察通道送回界面。

假设输入是空白文字且没有附件，内容判断为假，方法抛出错误，调用者的等待以失败结束；假设输入有效，方法继续到后面的接纳逻辑。这里的 Promise 返回 SessionPromptValue，也就是接纳回执。

注册工具时，程序把名称、参数说明和执行函数交给注册表。执行函数此时作为一个值保存，具体调用到来时才运行。箭头函数、对象方法和事件回调都要区分定义与调用。要让两个异步操作重叠，可以先分别启动，再用 `Promise.all` 汇总结果。全部成功时，它按传入顺序返回结果数组；任一项失败时，汇总的 Promise 就失败，其他已启动操作仍按各自流程收尾。

## 02.3 关键机制与设计取舍

### 回执返回后，驱动继续工作

![F02A：调用方等待接纳，驱动继续工作](../figures/F02A.png)

图 02A 并排展示两个等待范围。调用方等待 prompt 返回接纳对象；Agent 驱动在被唤醒后继续领取输入、调用模型和执行工具。

### 分析示例：注册不是执行

假设启动时运行三次“注册工具”的函数，随后模型只调用了一次文件读取工具。注册次数是 3，执行次数是 1。注册次数统计能力定义，执行次数统计实际调用。

![F02B：工具定义在启动时注册，在调用时执行](../figures/F02B.png)

图 02B 左侧保存工具定义，右侧使用定义执行调用。名称、参数和回调在启动时注册，read 的执行函数在具体调用到来时运行。

在文件读取插件中，`applyReadTool` 注册 `defineTool(...)`，对象里的 `async execute(...)` 是稍后执行的函数。读到函数对象时，要问“谁保存了它、谁以后调用它”，而不是假定控制流已经进入函数体。

### 回到任务接纳

用代码写法重走接纳流程：`prompt` 校验请求内容并解析目标；已识别的 requestId 直接返回回执；新请求构造用户消息，调用 `followup` 或 `steer`，再返回接纳对象。`followup` 把消息送入 Inbox 并唤醒驱动，后续模型请求与工具执行由驱动推进。

调试“提交成功但没有回答”时，沿 Inbox、驱动状态、模型请求和工具结果继续查。await prompt 已经结束，后台驱动仍在运行。

### 容易混淆的地方

“async 使函数内部所有动作并行”：连续写两个 await 时，第二个操作要等第一个返回后才开始。先启动两个操作、再汇总它们的 Promise，才给它们提供重叠推进的机会。

“类型合法就不会失败”：类型不能证明文件存在、网络可达或权限获准；运行时检查依然必要。

“工具对象里有 execute，所以启动已执行”：对象属性可以是一段尚未调用的函数。要追保存与调用位置。

## 02.5 理解检查与讲解问答

### 问题 1 · await 一个方法，是否等于等待整个用户任务完成？

讲解：由方法返回契约决定。等待接纳方法只获取回执；等待读取方法才获取读取结果。

### 问题 2 · 注册对象里写了 execute 函数，为什么没有立即读文件？

讲解：注册只是保存函数值与说明。后来发生具体工具调用时，框架才调用执行函数。

### 问题 3 · 类型说路径是字符串，是否证明文件存在？

讲解：没有。类型说明数据形状，文件存在、权限和读取成功需要运行时检查。
