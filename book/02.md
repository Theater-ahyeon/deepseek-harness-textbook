# 第 2 章｜TypeScript 基础与异步执行

本章学习任务：掌握值、对象、函数与类型的常见写法，理解 Promise、await 和回调的执行时机。

## 02.1 基本概念

变量是与值绑定的名称，例如 `path` 保存路径字符串。字符串表示文本，数字可以表示行号，布尔值表示真或假。对象组织相关属性，例如读取请求包含路径、起始行和行数，`request.content` 访问请求的内容属性。数组按索引保存一组值。数组索引通常从 0 开始，文件行号通常从 1 开始，窗口计算需要区分这两种编号方式。

函数封装可复用的处理逻辑，通过参数接收输入，通过返回值提供结果。方法是对象上的函数，例如 `agent.followup(message)` 调用 Agent 的消息接纳方法。类定义对象的结构和操作，由类创建的对象称为实例。接口和类型描述数据结构，例如将路径声明为字符串；文件是否存在则由执行时的文件服务检查。

TypeScript 在 JavaScript 的写法上增加类型说明。`const` 固定变量绑定，`let` 允许重新赋值；对象内部仍可能变化。冒号后面通常是类型，问号表示可缺省，`return` 把值返回调用者，`throw` 使当前路径失败。花括号既可能围住对象，也可能围住一组语句，要看它的位置。模块是单独组织代码的文件；`import` 引入别的模块，`export` 让别处能够使用本模块的名称。

Promise 表示异步操作的结果，状态包括等待中、成功和失败。`async` 函数返回 Promise，`await` 暂停当前函数的后续执行，等待该结果；JavaScript 运行时在此期间可以处理其他就绪工作。进程由操作系统管理，线程是进程内的执行路径。并发允许多项工作交错推进，并行使用多个执行资源在同一时刻处理工作。操作能否重叠，取决于启动和等待顺序。回调是供其他代码在约定时机调用的函数，例如事件监听器。阅读 `() => ...` 时，需要定位它的注册位置、调用者和触发条件。

JavaScript 提供执行语义，TypeScript 在其基础上增加静态类型检查，用于发现数据结构和调用方式中的问题。输入合法性、文件权限与资源可用性由运行时代码检查。等待外部 I/O 时，事件循环继续处理就绪任务，结果到达后恢复相应的异步函数。

### 常见语法与项目中的用途

阅读源码时，可以用下表查询常见写法；每段节选还配有逐行解释。

## 02.2 沿一个任务看完整流程

`await prompt(...)` 等待提交回执。prompt 校验内容，将消息提交给 Agent，再返回接纳结果。调用方收到回执后继续执行，Agent 驱动在后台推进任务，生成结果通过持续观察通道传回客户端。

假设输入是空白文字且没有附件，内容判断为假，方法抛出错误，调用者的等待以失败结束；假设输入有效，方法继续到后面的接纳逻辑。这里的 Promise 返回 SessionPromptValue，也就是接纳回执。

注册工具时，程序把名称、参数说明和执行函数交给注册表。执行函数此时作为一个值保存，具体调用到来时才运行。箭头函数、对象方法和事件回调都要区分定义与调用。要让两个异步操作重叠，可以先分别启动，再用 `Promise.all` 汇总结果。全部成功时，它按传入顺序返回结果数组；任一项失败时，汇总的 Promise 就失败，其他已启动操作仍按各自流程收尾。

## 02.3 关键机制与设计取舍

### 回执返回后，驱动继续工作

![F02A：调用方等待接纳，驱动继续工作](../figures/F02A.png)

图 02A 并排展示两个等待范围。调用方等待 prompt 返回接纳对象；Agent 驱动在被唤醒后继续领取输入、调用模型和执行工具。

### 分析示例：注册次数与执行次数

假设启动时运行三次“注册工具”的函数，随后模型只调用了一次文件读取工具。注册次数是 3，执行次数是 1。注册次数统计能力定义，执行次数统计实际调用。

![F02B：工具定义在启动时注册，在调用时执行](../figures/F02B.png)

图 02B 左侧保存工具定义，右侧使用定义执行调用。名称、参数和回调在启动时注册，read 的执行函数在具体调用到来时运行。

文件读取插件通过 `applyReadTool` 注册 `defineTool(...)` 定义，其中的 `async execute(...)` 以函数值的形式保存在注册表中。模型发出具体调用后，工具运行时才调用该函数并执行文件读取。注册位置和调用位置共同决定工具的执行时机。

### 接纳入口的异步执行顺序

`prompt` 首先校验请求并解析目标。已识别的 requestId 直接返回回执；新请求构造用户消息，调用 `followup` 或 `steer`，随后返回接纳结果。`followup` 将消息加入 Inbox 并请求唤醒驱动，模型请求与工具执行由驱动继续调度。

调试“提交成功但没有回答”时，沿 Inbox、驱动状态、模型请求和工具结果继续查。await prompt 已经结束，后台驱动仍在运行。

### 容易混淆的地方

“async 使函数内部所有动作并行”：连续写两个 await 时，第二个操作要等第一个返回后才开始。先启动两个操作、再汇总它们的 Promise，才给它们提供重叠推进的机会。

“类型合法就不会失败”：类型不能证明文件存在、网络可达或权限获准；运行时检查依然必要。

工具定义中的 execute 属性保存执行函数。注册完成后，具体调用仍需经过工具运行时，才能进入函数体。

## 02.4 源码研读

<a id="e02a"></a>

### E02A · async 返回的结果由方法契约决定

阅读任务：节选是 prompt 方法开头的输入校验。request 是入口接收的请求对象，内容不合法时方法抛出错误。时区、附件、消息入队与 accepted 返回位于后续逻辑，其主流程见第 1 章。

#### 实现详解

prompt 是客户端提交任务的异步入口，返回类型 SessionPromptValue 规定调用者拿到接纳回执。方法开头先检查请求是否包含可处理内容。content 是内容块数组，其中的文字块可以包含正文，非文字块承载图像、文件等材料。hasPromptContent 遍历这些块：文字去掉首尾空白后还有内容，或者存在非文字块，便通过这一项检查。

空数组、只含空字符串或只含空白文字的请求会在这里失败。入口构造 gateway/bad-request 类别的 RemoteError，附带“需要非空白文字或附件”的说明，然后终止当前方法。错误类别让远程调用方识别失败性质，说明文字帮助客户端显示原因；本次错误没有额外的结构化详情。因为检查发生在解析 Agent 和创建消息之前，这类请求不会经由后续路径进入 Inbox。

async 把方法结果组织成 Promise。方法中的 throw 会使这个 Promise 失败，客户端 await prompt 时便进入错误处理；合法请求跳过拒绝分支，继续检查时区、目标 Agent 和附件，最终获得接纳结果。入口中的 await 用来等待这些接纳工作。后台驱动处理模型与工具的时间线由后续事件呈现，调用方可在收到回执后继续响应界面操作。

比较两个输入便能看到完整顺序：提交三个空格且没有附件时，内容检查直接返回远程错误；只提交一个文件附件时，这项检查通过，随后还要解析附件凭据、接纳附件并绑定到消息。前者在入口结束，后者能否排队由后续接纳步骤决定。阅读异步方法时，先确定它承诺返回的结果，再沿各个等待点和错误分支观察，就能判断 await 结束时系统已经推进到哪一阶段。

代码类型：**真实源码摘录**。证据编号 [E02A](../evidence-index.md#e02a)；下表的数字是原文件行号。

```ts
  async prompt(request: SessionPromptRequest): Promise<SessionPromptValue> {
    if (!hasPromptContent(request.content)) {
      throw new RemoteError(
        'gateway/bad-request',
        'prompt content must include non-whitespace text or an attachment',
        {},
      )
    }
```

| 312 | if 与感叹号分别表示判断和取反 | 内容不符合要求时进入拒绝分支。 |
| 313 | throw 抛出一个 new 创建的错误对象 | 中断当前接纳路径，将失败返回调用方。 |
| 314 | 第一个字符串实参 | 指定远程错误类别 gateway/bad-request。 |

## 02.5 理解检查与讲解问答

### 问题 1 · await 一个方法，是否等于等待整个用户任务完成？

讲解：由方法返回契约决定。等待接纳方法只获取回执；等待读取方法才获取读取结果。

### 问题 2 · 注册对象里写了 execute 函数，为什么没有立即读文件？

讲解：注册只是保存函数值与说明。后来发生具体工具调用时，框架才调用执行函数。

### 问题 3 · 类型说路径是字符串，是否证明文件存在？

讲解：类型检查确认参数符合字符串类型；文件是否存在、权限是否允许以及读取是否成功，由运行时代码分别验证。
