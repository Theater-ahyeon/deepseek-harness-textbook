# 第 2 章｜TypeScript 基础与异步执行

本章学习任务：掌握值、对象、函数与类型的常见写法，理解 Promise、await 和回调的执行时机。

## 02.1 基本概念

程序通过变量名称与数据值绑定，例如用 `path` 保存路径字符串。常见值包括表示文本的字符串、表示行号的数字，以及表示真假的布尔值。对象将相关属性组合起来，比如读取请求带有路径、起始行和行数，通过 `request.content` 就能获取对应属性。数组按索引保存一组值，索引从 0 开始，这与通常从 1 起始的文件行号不同，进行窗口计算时要区分两者的编号规则。

开发中将可复用的逻辑封装为函数，经由参数接收输入并利用返回值交出处理结果。对象上附带的函数叫做方法，像 `agent.followup(message)` 会执行 Agent 的消息接纳动作。类设定了对象的内部结构与操作行为，依据类创建出来的就是对象实例。接口和类型专门描述数据的形状，像声明路径是字符串；而文件在磁盘上是否真实存在，交由运行时层面的文件服务负责检验。

TypeScript 语法在 JavaScript 基础上引入了类型声明。`const` 负责固定变量本身的绑定，`let` 支持后续重新赋值，无论哪种形式，对象内部依然允许发生变化。代码里的冒号后方通常跟随类型，问号指代该项可缺省，`return` 向调用方传递结果，`throw` 会令当前执行路径中断失败。花括号的作用取决于它的位置，既能包裹对象，也能框定一组语句。代码按模块拆分到单独文件中，用 `import` 引入外部逻辑，借由 `export` 开放自身名称。

异步操作开始后，程序通过 Promise 获取结果。结果尚未确定时，Promise 处于等待状态；操作完成后，它转为成功或失败。`async` 函数返回 Promise，`await` 暂停当前异步函数的后续执行，等待结果。在这段时间内，JavaScript 运行时仍可处理其他就绪工作。

进程由操作系统管理，线程是进程内的执行路径。并发允许多项工作交错推进，并行则使用多个执行资源同时处理工作。两项操作能否重叠，要看它们何时启动、何时等待，不能只凭 `async` 关键字判断。

回调是交给其他代码、由它在约定时机调用的函数，例如事件监听器。阅读 `() => ...` 时，需要找到它的注册位置、实际调用者和触发条件，才能判断这段函数体何时执行。

JavaScript 提供执行语义，TypeScript 增加静态检查，用于发现数据结构和调用方式中的错误。输入是否合法、权限是否获准、资源是否可用，由运行时代码检查。等待外部 I/O 时，事件循环继续处理就绪任务，结果到达后恢复相应的异步函数。

### 常见语法与项目中的用途

## 02.2 沿一个任务看完整流程

`await prompt(...)` 用于等待获取提交回执。该方法先检验输入内容，把消息移交 Agent，随后交出接纳结果。调用方拿到回执后恢复向下执行，而 Agent 驱动随之在后台向前推进具体任务，产出的结果经由持续观察通道推送给客户端。

倘若请求里仅有空白文字且缺乏附件，由于内容检验不通过，该方法会抛出异常，调用方的等待宣告失败结束；当请求带有有效内容时，程序继续向后推进接纳逻辑。此处的 Promise 返回的是 SessionPromptValue 形式的接纳回执。

程序在注册工具时，将名称、参数形状与执行函数交予注册表。此时执行函数只作为普通值存留，直到发生具体调用才会运转内部逻辑。针对箭头函数、对象方法及事件回调，阅读时需看清它是处于定义阶段还是调用阶段。若想让多项异步操作交错推行，要先分别启动它们，接着用 `Promise.all` 汇集进度。全部成功完成时，它按初始排列次序返回全部结果；只要发生某一项失败，汇总的 Promise 随即失败报错，其余已启动的工作继续按自身规律运转与收尾。

## 02.3 关键机制与设计取舍

### 回执返回后，驱动继续工作

![F02A：调用方等待接纳，驱动继续工作](../figures/F02A.png)

观察图 02A 并排呈现的两个等待范围。调用方正在等待 prompt 送回接纳回执对象；后台 Agent 驱动被唤醒后，随即转入获取输入、发起模型调用以及执行工具的后续流程。

### 分析示例：注册次数与执行次数

假设系统启动时执行了三次“注册工具”函数，后来模型仅发起一次读取文件的工具调用。此场景下的注册次数为 3，执行次数为 1。注册过程登记的是能力定义，执行过程体现工具的实际运行。

![F02B：工具定义在启动时注册，在调用时执行](../figures/F02B.png)

图 02B 左半边描绘了保存工具定义的过程，右半边体现运用该定义展开实际调用。名称、参数与回调函数都在启动时进入注册表，而 read 对应的执行函数只在具体请求抵达时才运转。

文件读取插件借由 `applyReadTool` 把 `defineTool(...)` 定义交出，内部编写的 `async execute(...)` 仅作为函数值留存在注册表里。直到模型传递了具体的调用动作，工具运行环境才会调用该函数去读取对应文件。工具最终的执行时机，由注册动作和后续调用共同决定。

### 接纳入口的异步执行顺序

调用 `prompt` 时程序先校验请求内容并解析接纳目标。遇到重复的 requestId 直接给出回执；面对新请求，它构建用户消息，转入 `followup` 或 `steer` 处理，最后送出接纳结果。`followup` 把消息推入 Inbox 并向驱动发出唤醒信号，模型访问和工具操作全由驱动接手调度。

当排查“成功提交却没有收到回答”的现象时，应当顺着 Inbox 记录、驱动状态、模型请求与工具产出这几项继续追溯。await prompt 结束说明接纳调用已经返回，后续任务进度仍需根据驱动状态和事件记录判断。

### 容易混淆的地方

澄清“async 会使内部所有动作并行”的误解：连续编写两个 await 语句时，第二个操作必须等待第一个获得结果才能起步。要先独立启动多项操作，再汇总它们的 Promise，这才给双方提供了重叠执行的空间。

澄清“类型合法就一定成功”的误解：静态类型无法确认文件存不存在、网络通不通畅或者操作权限有无获准；真实条件仍需借助运行时的代码检查应对。

工具定义里的 execute 属性负责留存执行逻辑。注册完成后，具体的调用请求还需要经由工具运行环境分发，才能真正触发该函数体。

## 02.4 源码研读

<a id="e02a"></a>

### E02A · async 返回的结果由方法契约决定

阅读任务：这段节选呈现 prompt 方法开头的输入校验。request 是入口接入的请求对象，若内容不合规，方法便会抛出异常。有关核对时区、处理附件、消息推入队列以及输出 accepted 回执的逻辑都在靠后的步骤中，其主流程可参考第 1 章。

#### 实现详解

prompt 方法充当客户端提交任务的异步入口，其返回的 SessionPromptValue 契约规定了调用方将拿到接纳回执。进入方法后，开头部分检查请求是否包含可被处理的内容。输入里的 content 是内容块数组，里面划分了携带正文的文字块，以及承载图像或文档等材料的非文字块。hasPromptContent 会去遍历该数组：只要文字块剔除首尾空白后依然存在内容，或者数组里带有非文字块，便能通过这项检测。

针对传递空数组、只发空字符串或全是空白文字的请求，操作在此就会遭到拦截。入口内部构造出一份 gateway/bad-request 分类的 RemoteError，带上“需要非空白文字或附件”的附带说明并停止当前方法向下运行。特定的分类标签用来向远程调用方表明失败的性质，附带说明辅助客户端向用户展示错误起因；本次报错不携带多余的结构化信息。由于这段拦截在判定 Agent 和组装消息之前发生，上述不良请求均无法沿着路径进入 Inbox 排队。

关键字 async 令方法的输出组装为一个 Promise。方法执行 throw 后，这个 Promise 进入失败状态，客户端 await prompt 时会接收到失败；合规内容则顺畅跳过拒绝分支，朝后延续时区查验、目标 Agent 匹配以及附件验证，直到交出接纳回执。入口包含的 await 用于等待这些前期接纳工作走完。后台驱动程序后续调度模型与工具的时序，将由别的异步事件体现；调用方拿着回执就能去响应其他的交互行为。

对比两种具体情况可以验证这段流程：当输入保留了三个空格却缺乏附件时，内容排查阻断执行并向客户端抛回远程报错；当请求带有一个文件附件时，内容检查得以通过，随之进入解析凭据、获取附件并绑定至消息的操作。前者的处理在此步直接结束，后者能否成功入队则依仗后面的步骤判别。在研读异步方法时，明确它宣称的回执结果，再沿着中间各个等待环节与失败分支梳理，便能掌握 await 动作解除时程序内部推进到了哪个进度。

代码类型：**真实源码摘录**。证据编号 [E02A](../evidence-index.md#e02a)；下表的数字是原文件行号。

```ts

    if (!hasPromptContent(request.content)) {
      throw new RemoteError(
        'gateway/bad-request',
        'prompt content must include non-whitespace text or an attachment',
        {},
      )
    }
```

| 312 | if 与感叹号分别表示判断和取反 | 内容不符合要求时进入拒绝分支。 |

## 02.5 理解检查与讲解问答

### 问题 1 · await 一个方法，是否等于等待整个用户任务完成？

讲解：这取决于方法自身约定的返回契约。调用并等待接纳方法时只为了得到那份接纳回执；去等待读取文件的操作，才会拿到真正的文件内容结果。

### 问题 2 · 注册对象里写了 execute 函数，为什么没有立即读文件？

讲解：注册时保存函数值及其参数说明。具体工具调用到来后，框架经过准入与分派，再调用执行函数。

### 问题 3 · 类型说路径是字符串，是否证明文件存在？

讲解：类型检查确认参数符合字符串类型。文件是否存在、权限是否允许以及读取是否成功，由运行时代码分别验证。
